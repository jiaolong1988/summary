## userName 的来源

[UserInfo.vue:27](vscode-webview://10tb6dvl59bnqrerfg2sjfhba4491u08mesup1pnbn6ep9s5rjra/src/layout/components/UserInfo/src/UserInfo.vue#L27) 里的 `userName` 是**读**的 Pinia 里的 user store，它自己不存储任何东西：



```js
const userName = computed(() => userStore.user.nickname ?? 'Admin')
```

## user.nickname 是登录后从后端接口拉取并缓存的

数据流是：

1. **登录时只拿到 token**。登录页提交的是 `username/password`（记住账号用的 `loginForm` 缓存是另一个东西），登录接口 `/system/auth/login` 返回的是 accessToken，**不包含昵称**。
2. **用户信息在路由守卫里拉取**。[permission.ts:75-77](vscode-webview://10tb6dvl59bnqrerfg2sjfhba4491u08mesup1pnbn6ep9s5rjra/src/permission.ts#L75-L77) 的 `router.beforeEach` 中，当已登录且 `isSetUser === false` 时调用 `userStore.setUserInfoAction()`。
3. **setUserInfoAction() 请求后端**。见 [user.ts:51-71](vscode-webview://10tb6dvl59bnqrerfg2sjfhba4491u08mesup1pnbn6ep9s5rjra/src/store/modules/user.ts#L51-L71)：
   - 调用 `getInfo()` → GET `/system/auth/get-permission-info`（[login/index.ts:36-38](vscode-webview://10tb6dvl59bnqrerfg2sjfhba4491u08mesup1pnbn6ep9s5rjra/src/api/login/index.ts#L36-L38)）
   - 后端返回 `user.nickname` 等字段
   - 赋值 `this.user = userInfo.user`
   - 同时缓存到 **localStorage**，key 为 `'user'`（`CACHE_KEY.USER`）
4. **下次刷新页面**时先读 localStorage 缓存，有缓存就直接用（同时后台 try/catch 静默刷新一次），没有缓存才重新请求。

## 小结

- 不是在**登录表单提交时**存的，而是在**登录成功后进入页面时**由路由守卫触发，从 `/system/auth/get-permission-info` 接口获取，然后存进 Pinia 内存 + localStorage（key 为 `user`）。
- `nickname` 是后端用户表里的**昵称**，和登录用的 `username`（账号）是不同字段——所以登录输入的名字不会直接显示为这里的 userName。
- `?? 'Admin'` 是兜底：当 nickname 为空（比如初始状态）时显示 `Admin`。
- 登出时 `loginOut()` 会调用 `deleteUserCache()` 清掉 localStorage 里的 `user` 缓存，并 `resetState()` 把 store 里 nickname 清空。
