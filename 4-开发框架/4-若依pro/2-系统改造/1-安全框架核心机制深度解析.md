## 一、认证信息如何存储

### 1.1 存储容器

核心存储由 `TransmittableThreadLocalSecurityContextHolderStrategy` 实现：

```
private static final ThreadLocal<SecurityContext> CONTEXT_HOLDER = new TransmittableThreadLocal<>();
```

- 使用 **`TransmittableThreadLocal`**（TTL）作为底层存储，而非普通 `ThreadLocal`
- 目的：解决 `@Async` 等异步执行时原生 `ThreadLocal` 的丢失问题
- 每个线程持有一个 `SecurityContextImpl` 对象

### 1.2 数据结构层级

```
TransmittableThreadLocal
  └── SecurityContextImpl
        └── Authentication (UsernamePasswordAuthenticationToken)
              ├── principal    → LoginUser（核心用户信息）
              ├── credentials  → null
              ├── authorities  → Collections.emptyList()
              └── details      → WebAuthenticationDetails（请求详情）
```

### 1.3 LoginUser 字段说明

| 字段            | 类型                | 含义                                   |
| :-------------- | :------------------ | :------------------------------------- |
| `id`            | Long                | 用户编号                               |
| `userType`      | Integer             | 用户类型（Admin/App 等）               |
| `info`          | Map<String, String> | 额外信息（昵称、部门ID等）             |
| `tenantId`      | Long                | 租户编号（多租户场景）                 |
| `scopes`        | List<String>        | 授权范围列表                           |
| `expiresTime`   | LocalDateTime       | Token 过期时间                         |
| `context`       | Map<String, Object> | 上下文临时缓存（@JsonIgnore 不序列化） |
| `visitTenantId` | Long                | 当前访问的租户编号                     |

### 1.4 存储流程（写入）

```

HTTP 请求到达
    │
    ▼
TokenAuthenticationFilter.doFilterInternal()
    │
    ▼
从 Header/Parameter 获取 Token（优先级：Header > Parameter）
    │
    ▼
调用 oauth2TokenApi.checkAccessToken(token) 校验 Token
    │
    ▼
构建 LoginUser 对象
    │
    ▼
SecurityFrameworkUtils.setLoginUser(loginUser, request)
    │
    ├── buildAuthentication: 创建 UsernamePasswordAuthenticationToken
    └── SecurityContextHolder.getContext().setAuthentication(authentication)
            │
            ▼
        存入 TransmittableThreadLocal
```

### 1.5 读取方式

```java

// 获取 Authentication
SecurityContext context = SecurityContextHolder.getContext();
Authentication auth = context.getAuthentication();

// 获取 LoginUser
LoginUser loginUser = (LoginUser) auth.getPrincipal();

// 工具类便捷方法
SecurityFrameworkUtils.getLoginUserId();       // 用户ID
SecurityFrameworkUtils.getLoginUserNickname(); // 昵称
SecurityFrameworkUtils.getLoginUserDeptId();   // 部门ID
```

### 1.6 双重存储机制

| 存储位置                 | 用途                                                       |
| :----------------------- | :--------------------------------------------------------- |
| TransmittableThreadLocal | 线程级安全上下文，供业务代码访问，支持异步线程传递         |
| HttpServletRequest 属性  | 供更早执行的 Filter 访问（如 ApiAccessLogFilter 日志记录） |

## 二、多用户并发时信息会乱吗？

**结论：不会乱，完全隔离。**

### 2.1 核心原理：ThreadLocal 线程隔离

```

┌─────────────────────────────────────────────────────┐
│                  线程池 Thread Pool                  │
│                                                     │
│  ┌───────────────┐  ┌───────────────┐  ┌─────────┐ │
│  │   线程 Thread-A │  │   线程 Thread-B │  │ 线程 C  │ │
│  ├───────────────┤  ├───────────────┤  ├─────────┤ │
│  │ TLA → 用户张三  │  │ TLB → 用户李四  │  │ → 用户王五│ │
│  │  ID: 1001     │  │  ID: 1002     │  │ ID: 1003│ │
│  └───────────────┘  └───────────────┘  └─────────┘ │
│                                                     │
│  每个线程的 ThreadLocal 互相物理隔离，存的是完全独立的对象   │
└─────────────────────────────────────────────────────┘
```

- Tomcat/Spring Boot 使用 **线程池** 处理请求
- 每个 HTTP 请求被分配到线程池中的一个线程
- 每个线程的 `ThreadLocal` 互相物理隔离
- 张三和李四同时请求，各存各的，不会串

### 2.2 为什么用 TransmittableThreadLocal？

普通 `ThreadLocal` 在**异步线程**中会丢失上下文：

- `@Async` 注解的方法
- `CompletableFuture` 异步任务
- 线程池提交的 Runnable/Callable

`TransmittableThreadLocal` 可以让父线程的上下文自动传递给子线程。

## 三、线程复用场景下的数据安全

### 3.1 销毁时机

**每个请求结束后自动销毁**，由 Spring Security 的 `SecurityContextHolderFilter` 保证。

### 3.2 完整生命周期

```
请求到达
  │
  ▼
SecurityContextHolderFilter.doFilter()
  ├── ① 保存当前 SecurityContext（oldContext）
  │
  ▼
TokenAuthenticationFilter.doFilterInternal()
  ├── ② 校验 Token
  ├── ③ 设置 LoginUser → SecurityContext
  │
  ▼
Controller 执行业务逻辑
  │
  ▼
请求返回
  │
  ▼
SecurityContextHolderFilter.doFilter() [finally 块]
  └── ④ 恢复/清空 SecurityContext → CONTEXT_HOLDER.remove()
          │
          ▼
      线程归还线程池，下次复用时已无脏数据
```

### 3.3 关键保障：try-finally 机制

Spring Security 自动注册的 `SecurityContextHolderFilter` 核心逻辑：

```
public void doFilter(request, response, filterChain) {
    SecurityContext oldContext = SecurityContextHolder.getContext(); // ① 保存旧上下文
    try {
        filterChain.doFilter(request, response); // ②③ 执行业务
    } finally {
        // ④ finally 块保证一定清理！即使业务抛出异常
        SecurityContextHolder.setContext(oldContext); // 恢复旧上下文(清空本次)
    }
}
```

### 3.4 三道防线

| 防线      | 机制                           | 说明                                      |
| :-------- | :----------------------------- | :---------------------------------------- |
| 第1道防线 | `SecurityContextHolderFilter`  | try-finally 强制清理，无论成功/失败/异常  |
| 第2道防线 | ThreadLocal 隔离               | 不同线程之间物理隔离，天然不会串数据      |
| 第3道防线 | TokenAuthenticationFilter 重设 | 新请求到达时会重新解析 Token 并覆盖旧数据 |

### 3.5 风险场景排查

| 场景                | 是否安全 | 说明                                  |
| :------------------ | :------- | :------------------------------------ |
| 同步 HTTP 请求      | ✅ 安全   | Filter 链自动清理                     |
| `@Async` 异步方法   | ✅ 安全   | TTL 自动传递上下文                    |
| `CompletableFuture` | ✅ 安全   | TTL 支持 ForkJoinPool                 |
| 定时任务            | ⚠️ 注意   | 定时任务线程不经过 Filter，需手动清理 |
| 绕过 Filter 操作    | ❌ 危险   | 直接操作 TTL 可能导致清理不及时       |

## 四、项目如何判断用户是否登录

### 4.1 全链路流程图

```
HTTP 请求到达
    │
    ▼
┌──────────────────────────────────┐
│ 第1层：URL是否需要认证？            │
│                                  │
│ • @PermitAll 注解 → 免登录         │
│ • permitAllUrls 配置 → 免登录     │
│ • 静态资源 → 免登录                │
│ • 其他 URL → 必须认证              │
└──────────────────────────────────┘
    │ 需认证
    ▼
┌──────────────────────────────────┐
│ 第2层：请求中是否携带 Token？       │
│                                  │
│ • 从 Header "Authorization" 获取 │
│ • 或从 Parameter "token" 获取    │
│ • 自动去除 "Bearer " 前缀        │
└──────────────────────────────────┘
    │ 有Token                │ 无Token
    ▼                        ▼
┌────────────────┐    ┌─────────────────────┐
│ 第3层：Token校验 │    │ Spring Security 拦截  │
└────────────────┘    │ → AuthenticationEntryPoint │
    │                        │
    ▼                        ▼
┌────────────────┐    ┌─────────────────────┐
│ 第4层：构建用户  │    │ 返回 401 UNAUTHORIZED│
│ 存入上下文       │    │ 前端跳转登录页        │
└────────────────┘    └─────────────────────┘
    │
    ▼
┌──────────────────────────────────┐
│ 第5层：Spring Security 最终判断     │
│                                  │
│ SecurityContext 中有有效 Authentication？ │
│ • 是 → 放行进入 Controller        │
│ • 否 → 401 未认证                 │
└──────────────────────────────────┘
    │
    ▼
┌──────────────────────────────────┐
│ 第6层：权限校验                    │
│                                  │
│ 当前用户是否有该接口访问权限？      │
│ • 是 → 执行业务逻辑               │
│ • 否 → AccessDeniedHandler → 403 │
└──────────────────────────────────┘
```

### 4.2 各层详细说明

#### 第1层：URL 权限配置

在 `BackendWebSecurityConfigurerAdapter.java` 中配置：

```java
authorizeHttpRequests(c -> c
    // 静态资源 - 免登录
    .requestMatchers("/*.html", "/*.css", "/*.js").permitAll()
    // @PermitAll 注解的接口 - 免登录
    .requestMatchers(permitAllUrls).permitAll()
    // 配置文件中配置的 URL - 免登录
    .requestMatchers(securityProperties.getPermitAllUrls()).permitAll()
    // 其他所有请求 - 必须认证
    .anyRequest().authenticated()
);
```

#### 第2层：Token 提取

```java

// Token 获取优先级：Header > Parameter
String token = request.getHeader("Authorization");     // 默认 Header
if (StrUtil.isEmpty(token)) {
    token = request.getParameter("token");            // 备用 Parameter（WebSocket 场景）
}
// 去除 "Bearer " 前缀
token = token.replace("Bearer ", "").trim();
```

#### 第3层：Token 校验（核心）

`OAuth2TokenServiceImpl.checkAccessToken()` 执行校验：

```
checkAccessToken(token)
    │
    ▼
① getAccessToken(token) - 两级缓存查询
    │
    ├── Redis 缓存命中 → 直接返回 ✅
    │
    ├── MySQL 数据库命中 → 回写 Redis → 返回 ✅
    │
    └── MySQL RefreshToken 命中（AccessToken 失效降级）
        → 转换为 AccessToken → 回写 Redis → 返回 ✅
    │
    ▼
② 校验结果判断
    ├── token == null → 抛出异常："访问令牌不存在" ❌
    ├── token 已过期  → 抛出异常："访问令牌已过期" ❌
    └── token 有效    → 返回 Token 信息 ✅
```

#### 第4层：构建 LoginUser

```java
LoginUser loginUser = new LoginUser()
    .setId(accessToken.getUserId())
    .setUserType(accessToken.getUserType())
    .setInfo(accessToken.getUserInfo())
    .setTenantId(accessToken.getTenantId())
    .setScopes(accessToken.getScopes())
    .setExpiresTime(accessToken.getExpiresTime());

// 存入 SecurityContextHolder
SecurityFrameworkUtils.setLoginUser(loginUser, request);
```

#### 第5层：Spring Security 最终判断

`AuthorizationFilter` 检查 `SecurityContext`：

```

SecurityContextHolder.getContext().getAuthentication()
    │
    ├── 为 null → 触发第6层（401未认证）
    └── 不为 null 且 isAuthenticated() == true → 放行
```

#### 第6层：拦截处理

| 场景             | 处理器                         | 响应码           | 含义       |
| :--------------- | :----------------------------- | :--------------- | :--------- |
| 未登录/Token无效 | `AuthenticationEntryPointImpl` | 401 UNAUTHORIZED | 请先登录   |
| 已登录但无权限   | `AccessDeniedHandlerImpl`      | 403 FORBIDDEN    | 无访问权限 |

### 4.3 判断登录的本质

```text
用户已登录 = SecurityContextHolder.getContext().getAuthentication() != null
            AND Token 在 Redis/MySQL 中存在且未过期
```

### 4.4 设计特点

| 特点           | 说明                                              |
| :------------- | :------------------------------------------------ |
| **无状态认证** | 完全基于 Token，Session 策略为 `STATELESS`        |
| **两级缓存**   | Token 先查 Redis，再查 MySQL，性能优先            |
| **自动降级**   | AccessToken 失效后，可用 RefreshToken 反查续期    |
| **注解驱动**   | `@PermitAll` 声明式免登录                         |
| **配置化扩展** | `backend.security.permit-all-urls` 配置免登录 URL |

## 附录：关键配置

### application.yml 配置示例

```yaml
backend:
  security:
    # Token 请求头名称
    token-header: Authorization
    # Token 请求参数名称（WebSocket 场景使用）
    token-parameter: token
    # mock 模式开关（开发调试用，线上必须关闭）
    mock-enable: false
    # mock 模式密钥
    mock-secret: test
    # 免登录 URL 列表
    permit-all-urls:
      - /admin-api/system/captcha/get
      - /admin-api/system/auth/login
    # 密码加密复杂度
    password-encoder-length: 4
```
